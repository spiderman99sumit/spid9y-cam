# Initial positioning check

An initial GitHub repository search for `spid9y` returned no matches. Exact-name web searches did not establish an obvious existing app with this spelling. This is a discoverability check, not evidence of broad brand clearance.

The category is established: [Iriun](https://iriun.com/) offers phone-as-webcam clients, and [DroidCam](https://www.droidcam.app/) offers USB/Wi-Fi phone webcam and OBS workflows. [DroidCam Classic's HD documentation](https://www.dev47apps.com/droidcam/hd-mode/) describes its particular free/paid HD limits; do not generalize those limits to every competitor or variant.

The useful niche is a free source-available workflow with local USB capture, browser camera controls, and clear performance/compatibility reporting. USB video itself is not a novel claim. Open-source competitors also exist; avoid first/only/best claims.

First audience: Windows OBS users who already own a spare Android phone, are comfortable with USB debugging, and want a low-cost facecam or second camera. Initial outreach should ask for beta feedback from a few relevant creators, not imply the software is proven across all devices.

The largest adoption barriers are setup complexity, sideloading/USB debugging, one-device physical validation, Android foreground requirements, no audio, and sharing OBS's single virtual-camera output. The next useful milestone is a small compatibility table backed by real tests, including reconnect behavior, 20-minute heat/charging sessions, frame rate in dim light, measured latency, and game/OBS load.

Potential exists as a focused community utility. These checks do not establish demand, revenue, or likely donation income. Publish a clear beta, gather concrete reports, then choose further features from observed problems.
